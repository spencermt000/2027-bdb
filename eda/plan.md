# EDA plan

Notebooks are generated by `build_notebooks.py` (nbformat) and share helpers in `utils.py`.
Rebuild + execute: `python eda/build_notebooks.py && jupyter nbconvert --to notebook --execute --inplace eda/0*.ipynb`

| Notebook | Data | Focus |
|---|---|---|
| 01_players_and_outcomes | players, player_career_successes | cohort makeup, UDFA share, draft slot vs career outcomes, accolade sparsity |
| 02_combine_results | combine_results | missingness/opt-outs, distributions by position, correlations, NGS scores vs draft slot |
| 03_combine_tracking | combine_tracking | drill coverage, 10 Hz tracking quality, 40-yd curves, tracked vs official 40, agility paths |
| 04_games_and_player_play | games, player_play | join integrity, role-specific null structure, situation context, EPA/WPA |
| 05_game_tracking_sample | game_tracking_2023-25 (5% game sample) | schema, cadence, kinematics, join coverage, scale estimate |

Open decision: full-data strategy for game tracking (duckdb vs parquet vs polars). Sample-based estimate in notebook 05: ~21M rows total, ~2 GB in pandas memory, so pandas is feasible but duckdb/parquet is cleaner. Change only `utils.sample_tracking` when decided.
